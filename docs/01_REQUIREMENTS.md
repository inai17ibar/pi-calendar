# 01 要件定義

## 1. 目的と対象

家庭のデスクに置く、個人用のGoogle Calendarビューア。
ユーザーが明示した必須事項は日/月の予定一覧、Pi起動時の自動表示、Mac/リモート/Pi内開発からの更新。
以下の性能値、読取専用、UI既定値は今回の**初期設計案**であり実測/ユーザー確認値ではない。

## 2. 機能要件

| ID | 優先度 | 要件 | 受入基準 |
|---|---|---|---|
| CAL-01 | MUST | 月間カレンダー | 前月/翌月/今日。日付選択でその日の予定を表示 |
| CAL-02 | MUST | 日別一覧 | 終日→時刻順。時刻、件名、カレンダー識別、進行中/次の予定 |
| CAL-03 | MUST | Google同期 | 選択カレンダーの追加/変更/削除が正常通信時に次回同期へ反映 |
| CAL-04 | MUST | 単一Googleアカウント、複数カレンダー | primaryから開始し選択可能。初期上限10件、選択解除した予定は表示しない |
| CAL-05 | MUST | 繰り返し/終日/複数日/跨日 | 例外移動・キャンセル・終了日時を正しく反映 |
| CAL-06 | MUST | 読取専用 | Googleへの予定insert/update/delete/patchを呼ばない |
| UI-01 | MUST | タッチ操作 | hover必須・右クリック必須・ダブルクリック必須の操作を設けない |
| UI-02 | MUST | 状態表示 | 同期中/最新取得時刻/オフライン/認証要更新/未取得を区別 |
| UI-03 | SHOULD | 設定 | 文字サイズ・日/月初期表示・月曜/日曜始まり・明暗テーマ |
| BOOT-01 | MUST | Pi起動時の自動表示 | 手操作なしでWeb+Worker+Chromiumが起動し既定画面へ |
| BOOT-02 | MUST | オフライン起動 | 保存済み範囲は表示。未取得は「取得できません」、空予定扱いにしない |
| BOOT-03 | MUST | 復旧 | サーバー/ブラウザの異常終了後に復帰。Google障害で再起動ループしない |
| DEV-01 | MUST | Macで開発 | mockモードで認証なしにUIとテストが動く |
| DEV-02 | MUST | Pi内でリモート開発 | SSH/Remote-SSH＋専用workspace、port3100、開発用DB |
| UPD-01 | MUST | Mac→Pi更新 | 指定commitを転送してPiでbuildし本番へ適用 |
| UPD-02 | MUST | Pi内→本番更新 | workspaceから同一release手順を呼べる |
| UPD-03 | MUST | 失敗時復旧 | build失敗時は本番無変更。適用失敗時に前版へ戻せる |
| UPD-04 | MUST | 画面更新 | 切替後にリリースIDを検出し自動再読み込み。旧JSを放置しない |
| UPD-05 | MUST | バージョン確認 | 現在のcommit/release ID、更新結果を確認できる |

## 3. 非機能の初期目標

起動：正常なPi環境で電源投入から表示まで90秒以内を目標（実測後に調整）。
ローカルAPI起動後：保存済み予定を5秒以内に表示。ネット接続を待たない。
タッチ：読み込み済みの日/月切替は概ね200ms以内の視覚応答を目標。
同期：今日と表示中の月は60秒周期。正常通信時は更新が約90秒以内に反映することをテスト。
常用：24時間表示、日付跨ぎ、ネット切断/復帰、再起動をテスト。
文字：1280×853 CSS px相当でも月＋日一覧が使えること。物理解像度とCSS解像度を混同しない。
容量：端末1台、アカウント1件。最初から多数ユーザー/大量イベント向けの基盤は作らない。

## 4. 明確な非対象

Google予定の編集、音声アシスタント、AI要約、天気、ニュース、Tasks、通知音、メール。
インターネットへ公開するサイト、企業SSO、マルチテナント、常駐CIランナー。
画面から任意コードをダウンロード/実行するアップデータ。MVPの更新操作はSSH/CLIでよい。
自動的な最新main追従、OS自動アップグレード、無停止/二重化、オフライン予定編集。

## 5. 定義

「オフライン対応」＝ローカルサーバーが動いていれば、ネットなしでSQLite内の取得済み予定を表示。
初回取得していない期間を創作しない。Service Workerによる全資産オフライン化はMVPでは不要。
「同期」＝Google→Piの読み取り。「更新」＝プログラムのリリース切替。
「リモート開発」＝Piの開発フォルダを編集。「本番更新」＝確認済みcommitをreleaseへ昇格。

## 6. 不明点の扱い

RAM、OS、接続名、認証済みアカウント等は実装の障害にならない範囲では設定値として残す。
物理ボタンやセンサーを勝手に前提にしない。ヘッドレスOSならGUI追加は別途承認事項。
