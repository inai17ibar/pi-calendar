# 02 画面・操作仕様

## 初期画面案

横置き3:2。初期表示は「月＋今日の一覧」。月を大きく見せる領域と、右側に日別一覧を設ける。
「日」タブでは選択日を全幅の一覧にする。基本要件は両方の表示を持つこと。

```text
┌──────────────────────────────────────────────────────┐
│ 10月3日(土)  14:20    [今日] [日] [月] [設定]          │
├─────────────────────────────────┬────────────────────┤
│ ＜   2026年10月   ＞            │ 10月3日の予定      │
│ 月 火 水 木 金 土 日            │ 終日  サンプル     │
│      ...                        │ 15:00 次の予定     │
│ 日付セル＋短い件名/色            │ 17:30 サンプル     │
│ ...                             │                    │
├─────────────────────────────────┴────────────────────┤
│ 最終取得 14:19    接続済み            version: <sha>   │
└──────────────────────────────────────────────────────┘
```

図の予定は架空。最終取得時刻はcalendarごとにも確認できる。
通信の成功と「予定がない」を区別し、部分失敗も隠さない。

## 寸法・視認性の設計目安

| 項目 | 初期値 |
|---|---|
| テストviewport | 1920×1280、1536×1024、1280×853、1024×683 CSS px |
| 通常文字 | 20–24 CSS px、拡大モードを追加 |
| 時計 | 36–48 CSS px。秒の常時再描画は不要 |
| 操作対象 | 最小48×48 CSS pxを設計目標、隣接操作と間隔を空ける |
| 幅が不足 | 月/日を別画面へ。縮小して文字を読めなくしない |
| スクロール | 一覧内の縦スクロール。画面全体の二重スクロールを避ける |

これは本製品向けの初期値。実機で指/視距離を確認する。

## 月表示

週始まりは初期月曜、変更可。最大6週で高さを固定。前後月の日付も月の識別を付ける。
セル内は上限件数を表示し、残りを「他N件」とする。件数から予定が消えたと誤解させない。
日をタップすると選択し、日別パネルを更新。月ナビゲーションだけで設定保存APIを連打しない。
跨月の予定は対象月に重なる部分を表示。前後月セルの情報は該当月スナップショットから取得する。
未取得セルは「未取得」とし、ドットなし=空とはしない。

## 日表示

終日イベントは上部。時刻付きは開始順、同時刻は終了/IDで安定ソート。
当日より前から継続する予定も含め、日付区間との重なりで抽出する。
予定詳細はモーダル/サイドパネル。説明HTMLはプレーンテキスト化し、リンク自動実行なし。
キーボードがない前提なのでGoogleログインや長文入力は管理用Mac/CLIへ案内する。
予定がない日のみ「予定はありません」。取得失敗はその文言にしない。

## 日付・時計

表示timezone初期値Asia/Tokyo。OSのtimezoneに任せずアプリ設定を用いる。
時計は注入可能なClock経由。0時に今日ハイライト/日別一覧/同期対象を更新。
閲覧している過去の日を0時に突然変えない。今日追従フラグを保持する。
非操作時5分で今日へ戻る機能は設定でOFF可能。初期はOFFでよい。

## 通信・エラー時の状態

`initializing` / `not_configured` / `syncing` / `fresh` / `stale` / `offline` / `auth_required` / `partial_error`。
古いデータは消さず、取得時刻を添える。同期成功から5分超をstaleの初期目安にする。
Google auth失敗でも背景をエラー画面一色にしない。未設定時はセットアップ案内＋時計。

## 版切替とUI回復

15秒ごとに `/api/version` をno-storeで確認。APIエラーだけでは画面を再読み込みしない。
release ID変更後に同じ新IDを2回確認し、選択日/表示モードをsessionStorageへ保存してreload。
30秒のcooldownと連続リロード上限でループを防ぐ。reload後には保存状態を安全に復元する。
フロントエンドのErrorBoundaryにはローカル状態を保って再接続する経路を設ける。
後述kiosk supervisorだけではハング中のブラウザを判定できない。プロセス終了復旧と分けてテストする。

## 見た目

白/暖かいグレー＋小数のカレンダーカラー。ダークモードは別トークン。
外部CDN、オンラインフォント、天気画像に依存しない。日本語フォントはOSまたは配布許諾を確認して同梱。
アニメーションは短く、prefers-reduced-motionを尊重。色だけに意味を依存させない。

## M1追加：Googleカレンダー風の週表示（2026-10-09）

白いグリッド、青い今日/選択表示と月・週・日の切替を使う。週は選択日と週始まり設定から7日を算出し、月/年を跨ぐ日付範囲を見出しに表示する。必要な月のmock APIをすべて取得し、calendarId/eventIdで重複除去。同じ取得範囲の通信失敗時はサンプルを保持し、新しい範囲を未取得として扱う。

終日は時間軸の上に置き、複数日は各日の欄に継続矢印を表示。時刻予定は0–24時の時間軸で日境界に切り分け、重複する時間帯は列分けする。短い予定のタッチ対象は48px以上のため、見た目の高さは最短40分相当。実時間はラベルと詳細で確認できる。日付/終日見出しはスクロール中も固定し、狭い幅は週領域内で横スクロールする。Google同期とPi OS設定は対象外。
